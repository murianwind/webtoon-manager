# 웹툰 구독 관리

네이버웹툰 무료 회차를 자동으로 챙겨서 받아주는 프로그램입니다.
"좋아하는 작가/태그를 한 번만 등록해두면, 그 뒤로는 신경 안 써도 알아서 받아준다"가 핵심입니다.

## 핵심 개념 — 웹툰을 4개 탭으로 나눠서 관리합니다

- **웹툰 전체목록**: **지금 구독 중인 웹툰**과, **구독은 안 하지만 계속 지켜보고 싶은(관리하고 싶은) 웹툰**이 모이는 곳입니다. 네이버 연재작과(설정에서 켜두면) 카카오웹툰 연재작이 함께 보이고, 각 작품에 플랫폼 배지("네이버"/"카카오")와 "구독"/"목록제외" 버튼이 있습니다.
- **구독해제**: **예전엔 구독해서 받았지만, 더 이상 자동으로 다운로드받고 싶지 않은 웹툰**입니다.
- **제외됨**: **아예 관심 없다고 정한 웹툰**입니다.

"구독해제"나 "제외됨"에 있는 웹툰을 **다시 받고 싶으면 "구독"**을 누르면 바로 재개되고, **다운로드는 안 받아도 목록에서 다시 보고 싶으면(관리하고 싶으면) "목록으로"**를 누르면 "웹툰 전체목록"으로 돌아갑니다. 즉 "구독"은 "지금부터 자동으로 받기 시작", "목록으로"는 "다운로드는 안 받지만 전체목록에서 계속 찾아볼 수 있게"를 뜻합니다. **다만 카카오웹툰은 이 프로그램이 직접 다운로드하지 않아서 "구독"의 의미가 다릅니다** — 아래 [카카오웹툰 자세히](#카카오웹툰-자세히) 참고.

**"구독해제" 탭에는 실제로 한 번이라도 구독했던 웹툰만 남습니다** — 구독한 적 없이 "제외됨 → 목록으로"만 거친 웹툰은 이 탭에 안 섞입니다. 그리고 한 번이라도 구독 이력이 있는 웹툰은, "목록으로"를 여러 번 오가도(구독해제 ↔ 목록으로 ↔ 제외됨 ↔ 목록으로 ...) 그 이력이 계속 남아서, **네이버 자체 목록(요일별 전체목록)에 없는 완결·장기휴재 작품이어도 "웹툰 전체목록"에서 항상 다시 찾을 수 있습니다.** 반대로 구독한 적 없는 웹툰을 "목록으로" 보내면, 네이버(또는 카카오) 자체 목록에 이미 없는 작품(완결·장기휴재)은 그 목록에서도 안 보일 수 있습니다(플랫폼 쪽 데이터 자체의 한계라 저희 쪽에서 되돌릴 방법이 없습니다).

혹시 예전 버전을 쓰다가 이 구분이 꼬인 기록이 있거나, 실수로 완전히 사라진 웹툰을 titleId만으로 복구하고 싶으시면 **"설정" 탭의 "구독해제 관리"**에서 정리할 수 있습니다(네이버 전용).

## 이런 분께 추천합니다

- 좋아하는 작가가 새 작품을 냈는지 매번 확인하기 귀찮은 분
- 웹툰이 완결됐는지, 구독을 계속 유지할지 매번 고민하기 귀찮은 분
- 서버 콘솔이나 명령어 없이, **웹 브라우저 하나로 전부 관리**하고 싶은 분
- 회차가 며칠~몇 주씩 밀려도, 한꺼번에 몰아 받다가 문제 생기는 게 걱정되는 분
- 다운로드 폴더에 파일이 계속 쌓이는 게 신경 쓰이는 분 (완결작을 별도 폴더로 자동 정리)

## 무엇을 자동으로 해주나요

- **작가/태그 등록** — 좋아하는 작가나 장르 태그를 등록해두면, 그 작가의 신작이나 그 태그에 새로 올라온 작품을 알아서 구독합니다. 작가는 등록 시점에 이미 구독 중인 작품이 하나도 없어도(오랫동안 활동이 뜸했던 작가 포함) 신작이 나오면 놓치지 않고 잡아냅니다. 구독하면 그 작품의 작가가 자동으로 등록되는데, **작품에 작가와 원작자가 따로 있으면 원작자가 등록됩니다**(원작자만 있어도 원작자, 원작자가 없으면 글 작가). 작가 목록에는 원작자도 후보로 나오고 "(원작)"으로 표시됩니다. 카카오페이지도 같은 규칙입니다 — 작품 "정보"의 글/그림/원작 구분을 읽어서 원작자가 있으면 원작자를, 없으면 글 작가를 등록합니다(그림 작가는 등록하지 않고, 정보를 못 받으면 등록을 건너뜁니다). "작가/태그 관리"의 **"지금 전체 재동기화"**는 카카오웹툰 관리를 켰으면 카카오페이지 작품도 함께 처리합니다 — 구독/구독해제/목록/제외됨 전부의 작품 정보를 받아 같은 규칙(원작자 우선, 없으면 글 작가, 그림 작가는 제외)으로 관심 작가를 채우고 파일명 템플릿용 글 작가도 저장합니다. 구독할 때 작품 정보를 못 받았거나 이 기능이 생기기 전에 구독한 작품도 이걸로 채워집니다(제외된 작품의 작가는 "전체 작가 목록"에만 올라가고 켜지지 않으며, 사용자가 꺼 둔 작가는 그대로 둡니다). 작품마다 결과가 실행 이력에 남습니다
- **카카오웹툰 관리** — "웹툰 전체목록"/구독해제/제외됨/다운로드 리포트에 카카오웹툰도 같이 다룰 수 있습니다 (설정에서 켜야 함, 기본 꺼짐). 신작·새 회차 발견과 목록 관리에 더해, 카카오페이지 작품의 무료/대여 중 회차를 수동으로도, 정해진 시각에 자동으로도 받습니다(잠긴 회차는 기다무 대여권이 있으면 그것으로 엽니다) — 자세한 내용은 [카카오웹툰 자세히](#카카오웹툰-자세히) 참고
- **카카오웹툰 작가 신작 알림** — "카카오웹툰 관리"와 별개로, 관심 있는 카카오웹툰 작가를 등록해두면(완결작 포함 전체 스캔) 그 작가의 새 시리즈가 나올 때 제목과 ID를 디스코드로 알려줍니다. 처음 등록한 작가의 첫 스캔에서는 기존 작품 전체를 조용히 기준선으로만 저장하고, 그 이후에 나오는 진짜 신작부터 알림이 갑니다
- **자동 다운로드** — 정해진 시간마다 새 회차를 확인해서 받습니다(네이버, 카카오페이지). 다운로드 스케줄은 **여러 개 등록할 수 있고, 스케줄마다 받을 대상(네이버 / 카카오페이지 / 둘 다)을 고릅니다** — 예를 들어 네이버는 매시간, 카카오페이지는 하루 세 번처럼 따로 정할 수 있고, 등록한 스케줄은 나중에 고칠 수 있습니다. 자동 다운로드는 **아직 받지 않은 회차만** 받습니다(수동 다운로드는 이미 받은 회차도 다시 받을 수 있습니다)
- **다운로드 리포트** — 원하는 시각에, 그 사이 받은/실패한 작품을 모아 디스코드로 요약해서 보내줍니다. 별도의 웹툰 뷰어 서버 주소를 등록해두면 "바로가기" 링크까지 붙습니다. **구독은 안 했지만 새 에피소드가 올라온 미등록 웹툰**도 함께 알려주고(끌 수 있음, 네이버+카카오 공통), 바로가기 옆에 "목록 제외" 링크가 붙어서 링크 하나로 바로 제외 처리할 수 있습니다(실수로 눌리는 걸 막기 위해 확인 페이지를 한 번 거칩니다) **카카오페이지를 받았으면 리포트에 "[카카오]"와 "[네이버]" 표시가 붙고**, 카카오 작품은 받은 회차 수와 범위(예: `쌍갑포차 · 3개 회차(409~411번)`)와 바로가기(웹툰 뷰어에 있으면 뷰어 링크, 없으면 카카오페이지 링크)가 나옵니다. 네이버만 받았을 때는 예전 형식 그대로입니다. 등록하지 않은 작품의 "새 에피소드"는 **같은 회차를 한 번만 알립니다**(UP 표시가 남아 있어도 하루에 여러 번 받는 리포트에 반복되지 않고, 더 새로운 회차가 나오면 다시 알림. 테스트 발송은 전부 보여주고 기록하지 않음). 카카오 수동 다운로드 이력처럼 플랫폼 열이 생기기 전 이력은 시작할 때 자동으로 바로잡습니다.
- **완결 알림** — 구독 중인 작품이 완결되면 디스코드로 알려주고, 그 자리에서 버튼으로 "구독해제" 또는 "알람 제외"를 바로 선택할 수 있습니다. **카카오페이지도 지원합니다**: 작품이 완결(작품 정보의 `on_issue`가 완결)로 표시돼 있고 **받을 회차를 다 받았을 때만** 알립니다(완결인데 잠긴 회차나 못 받은 회차가 남았으면 아직 알리지 않음). 메시지에는 "[카카오]"가 붙고 같은 두 버튼이 나옵니다. 봇이 꺼져 있어서 못 보냈으면 알렸다고 기록하지 않고 다음 실행 때 다시 보내며, 다시 연재로 돌아온 작품은 기록을 초기화해 다음 완결 때 다시 알립니다. 구독해제하면 아카이빙의 완결 자동 이동 대기열에 들어갑니다(네이버와 동일, 설정이 켜져 있을 때). 네이버도 디스코드 버튼으로 구독해제했을 때 이 대기열에 들어가도록 함께 고쳤습니다.
- **아카이빙** — 지정한 웹툰(또는 웹툰 레코드 없는 임의 폴더 — 카카오웹툰 등)을 정해진 주기마다(마지막 회차는 남기고) 별도 보관 폴더로 자동 정리합니다. 완결된 작품을 구독해제하면 전체를 한 번에 보관 폴더로 옮기는 것도 가능합니다. 파일명을 원하는 형태로 바꿔주는 프리셋 기능, 카카오페이지 작품이면 공식 표지를 새로 받아서 옮기는 기능도 있습니다 **카카오페이지 웹툰도 "웹툰으로 등록"에 나옵니다**(카카오웹툰 관리를 켰고 구독 중인 작품, "[카카오]"로 표시) — 등록하면 주기 실행/수동 실행/완결 처리 이동 모두 **카카오페이지 다운로드 폴더**에서 파일을 옮기고(작품 폴더는 카카오 폴더 이름 규칙), 보관 폴더 쪽 규칙(마지막 회차 보존, 이름 충돌 정책, 파일명 프리셋)은 네이버와 같습니다. 파일명 템플릿의 `{author}`는 네이버처럼 **"글" 작가**입니다(작품 정보의 글/그림/원작 구분에서 구독할 때와 받을 때마다 저장해 두며, 아직 저장 전인 작품은 목록의 작가 이름으로 대신합니다). 대상 id는 내부적으로 `kakao_<시리즈 번호>`라서 네이버 작품과 번호가 겹치지 않습니다. **"완결 구독해제 시 자동 이동"도 카카오에 똑같이 적용됩니다** — 완결이고 받을 회차를 다 받은 카카오 작품을 구독해제하면(화면이든 디스코드 완결 알림의 "구독해제" 버튼이든) 이동 대기열에 들어가 다음 아카이빙 주기에 마지막 회차까지 카카오 다운로드 폴더에서 옮겨지고, 다 옮기면 빈 폴더는 정리됩니다(옮길 곳은 등록한 대상의 폴더, 없으면 완결 자동이동 기본 경로).
- **쿠키 만료 알림** — 성인 인증이 만료되면(로그인이 풀리면) 디스코드로 알려줍니다
- **안전한 다운로드** — 회차가 많이 밀려도 한 번에 몰아받지 않고, 적당히 나눠서 쉬어가며 받습니다
- **다운로드 실패 요약** — 실패한 게 있으면 한 번에 모아서 디스코드로 알려줍니다
- **정보 파일(info.xml/커버) 자동 생성** — 다운로드 폴더마다 만화 뷰어(Komga 등)가 읽을 수 있는 정보 파일을 만듭니다. 글작가/그림작가/원작자를 구분해서 담고, 장르는 네이버 내부 코드가 아니라 한국어 이름으로, 연령 등급은 "전체연령가"/"전체이용가"처럼 표현이 다른 것도 하나로 통일해서 씁니다. 메타 동기화(수동 실행 또는 정기 스캔)를 돌릴 때마다 항상 최신 정보로 다시 씁니다 **카카오페이지도 받으면 작품 폴더에 info.xml과 표지(cover.jpg)를 만듭니다** — 연령 등급은 "15세 이용가", "18세 이용가", 그 외는 모두 "전체이용가"로 적고, info.xml은 받을 때마다 최신 정보로 다시 쓰며 표지는 없을 때만 받습니다(글은 Writer, 그림은 CoverArtist, 원작은 Notes에 "원작: …", 테마 키워드는 Tags에 적습니다. 작품 정보를 못 받으면 작가 이름 전부를 Writer에 적습니다). **"수동 실행 > 메타 동기화"는 받은 작품 폴더의 info.xml과 커버를 최신 정보로 새로 교체합니다**(네이버/카카오페이지 모두, 카카오웹툰 관리를 켰을 때 카카오 포함 — 예전 카카오웹툰에서 받은 커버도 카카오페이지 표지로 바뀌고, 한 작품이 실패해도 나머지는 계속하며 받기 실패 시 기존 파일은 유지). 다운로드할 때는 기존처럼 커버가 없을 때만 받습니다.

## 설치하기 (Docker / Portainer 기준)

로컬에서 코드를 빌드할 필요 없이, 미리 만들어진 이미지를 받아서 바로 실행합니다.

1. Portainer → **Stacks → Add stack → Web editor** 선택
2. 아래 내용을 그대로 붙여넣기

   ```yaml
   services:
     webtoon-manager:
       image: ghcr.io/murianwind/webtoon-manager:latest
       container_name: webtoon-manager
       restart: unless-stopped
       labels:
         - "com.centurylinklabs.watchtower.enable=true"
       ports:
         - "${WEB_PORT:-8000}:8000"
       environment:
         DOWNLOAD_ROOT: /webtoon_download
         ARCHIVE_ROOT: /webtoon_archive
         DATABASE_PATH: /data/webtoons.db
         COOKIE_FILE_PATH: /cookies/${COOKIE_FILE_NAME:-cookies.json}
         RCLONE_CONFIG_PATH: /rclone-config/rclone.conf
       volumes:
         - ${WEBTOON_DOWNLOAD_HOST_PATH}:/webtoon_download
         - ${WEBTOON_ARCHIVE_HOST_PATH}:/webtoon_archive
         - ${APP_DATA_HOST_PATH}:/data
         - ${COOKIE_DIR_HOST_PATH}:/cookies:ro
         - ${RCLONE_CONFIG_HOST_PATH}:/rclone-config
   ```

3. 아래로 스크롤해서 **Environment variables**에 다음을 채워 넣기

   | 이름 | 값 예시 | 설명 |
   |---|---|---|
   | `WEBTOON_DOWNLOAD_HOST_PATH` | `D:\Downloads\Webtoon\Webtoon_Download` | 실제로 웹툰이 저장될 폴더 |
   | `WEBTOON_ARCHIVE_HOST_PATH` | `D:\Downloads\Webtoon\Archive` | 아카이빙된 파일이 보관될 폴더 |
   | `APP_DATA_HOST_PATH` | `D:\WebtoonManagerData` | 설정/DB를 저장할, 비어있는 폴더 |
   | `COOKIE_DIR_HOST_PATH` | `D:\WebtoonManagerData\cookies` | 네이버 로그인 쿠키 파일이 들어있는 폴더 |
   | `COOKIE_FILE_NAME` | `cookies.json` | 위 폴더 안 쿠키 파일 이름 |
   | `RCLONE_CONFIG_HOST_PATH` | `D:\WebtoonManagerData\rclone` | rclone.conf 파일이 들어있는 폴더 (안 쓰실 거면 이 줄 자체를 지우세요) |
   | `WEB_PORT` | `8000` | 브라우저로 접속할 포트 (이미 쓰는 포트면 다른 숫자로) |

4. **Deploy the stack** 클릭
5. 브라우저에서 `http://<서버주소>:포트`로 접속

성인 인증이 필요한 작품을 받으시려면, 브라우저 확장 프로그램(Cookie-Editor 등)으로 comic.naver.com 로그인 상태에서 쿠키를 JSON 파일로 내보내서 `COOKIE_DIR_HOST_PATH` 폴더에 넣어두시면 됩니다. 성인 웹툰을 안 받으실 거면 이 단계는 건너뛰셔도 됩니다.

아카이빙 기능(로컬)을 안 쓰실 거면 `WEBTOON_ARCHIVE_HOST_PATH`/`ARCHIVE_ROOT` 두 줄(환경변수 + volumes)을 통째로 지워도 됩니다 — 그러면 "아카이빙" 탭에 설정 안내 화면만 뜨고, 나머지 기능(구독/다운로드/알림 등)엔 전혀 영향 없습니다. rclone 원격만으로 아카이빙을 쓰실 거면 로컬 쪽은 아예 없어도 됩니다.

## 처음 켠 뒤 해야 할 일

1. **"설정" 탭**에서 디스코드 웹훅 URL을 입력합니다(완결 확인 버튼까지 쓰고 싶으시면 봇 토큰과 채널 ID도 함께). 웹훅을 입력해야 그 아래 "실행 스케줄"/"다운로드 리포트" 설정이 나타납니다 — 신작 알림이나 리포트를 보낼 곳이 있어야 그 세부 설정이 의미가 있기 때문입니다. 카카오웹툰도 같이 쓰고 싶으시면 "다운로드 리포트" 안의 "미등록 웹툰 중 새 에피소드 섹션 포함"을 켜시면 그 아래 "카카오웹툰 관리"가 나타나고, 거기서 켜시면 됩니다.
2. **"웹툰 전체목록" 탭**에서 이미 보고 있던 작품을 찾아 "구독" 버튼을 누릅니다.
3. **"작가/태그 관리" 탭**에서 좋아하는 작가 이름을 검색해서 등록하거나, 태그 목록에서 관심 있는 장르를 추가합니다. 카카오웹툰 작가도 같은 화면에서 등록할 수 있습니다.

이렇게 한 번만 해두시면, 그다음부터는 신작이 나와도 자동으로 구독되고 자동으로 받아집니다.

## 화면 구성

| 탭 | 하는 일 |
|---|---|
| 웹툰 전체목록 | 네이버(및 켜두면 카카오)의 연재작을 훑어보고 구독/제외를 결정하는 곳. 구독 중인 작품과, 구독은 안 해도 계속 지켜보고 싶은 작품이 여기 모입니다. 검색, "구독중만/아직 미등록만" 필터, "신작만/휴재만/새 에피소드만" 배지 필터, 체크박스로 여러 개 골라서 한 번에 "제외됨"으로 옮기는 기능이 있습니다 |
| 구독해제 | 실제로 한 번이라도 구독했다가 지금은 안 받는 작품 목록 ("구독"으로 다시 받거나, "목록으로"로 전체목록에만 남기기) |
| 제외됨 | "이건 안 볼래"라고 확실히 정한 작품 목록 (마찬가지로 "구독"/"목록으로" 가능) |
| 수동 다운로드 | 작품을 검색해서 원하는 회차만 골라 받는 곳 (네이버, 카카오페이지 — 카카오페이지는 회차 표에서 이미 받은 회차도 다시 받을 수 있음) |
| 작가/태그 관리 | 자동 구독을 위한 관심 작가/태그(네이버+카카오웹툰)를 등록·해제하는 곳 |
| 이력 | 다운로드 이력, 실행 이력(신작스캔/다운로드/리포트/아카이빙), 아카이빙 이력을 한 곳에서 확인·검색하는 곳 |
| 수동 실행 | 신작 스캔/다운로드/메타 동기화/리포트 발송/아카이빙을 즉시 실행하고 진행 상황을 보는 곳 |
| 아카이빙 | 같은 이름 파일 처리 정책(공통 설정), 파일명 변경 프리셋, 웹툰별·폴더별 보관 폴더 지정, 완결 자동이동 설정, 폴더 일괄 이동 |
| 설정 | 디스코드 알림 → 실행 스케줄/다운로드 리포트 → 카카오웹툰 관리 순으로 단계적으로 나타남(아래 [설정 화면 순서](#설정-화면-순서) 참고), 작가 자동 등록, 구독해제 관리, 백업/복원 |
| 도움말 | 이 문서(README)를 그대로 보여주는 곳 |

각 작품 카드에 뜨는 표시:
- **신작** — 새로 올라온 작품으로 표시된 것 (네이버/카카오 각 플랫폼 API의 값 그대로)
- **완결** — 연재가 끝난 작품 (네이버만 — 카카오는 요일별 목록만 다루므로 완결작 자체가 목록에 없음)
- **휴재** — 잠시 쉬고 있는 작품
- **UP** — 새 회차가 올라왔다고 표시된 것 (네이버/카카오 각 플랫폼 API의 값을 그대로 저장해서 씁니다). 다만 이 값은 개별 작품 조회 API에는 없고 **"웹툰 전체목록" 탭을 열어서 전체 목록을 훑을 때만** 얻을 수 있어서, 특정 작품의 UP 상태는 그 탭을 최소 한 번 열어야 갱신됩니다. 한 번 갱신되면 어느 탭에서 보든 동일한 값이 표시됩니다("구독해제"/"제외됨" 탭도 조회 시점에 다시 확인해서 붙여줍니다).
- **네이버/카카오 플랫폼 배지** — 어느 플랫폼 작품인지 표시
- **구독중/구독해제/제외됨 배지** ("웹툰 전체목록" 탭에서만) — 구독해제 배지는 실제로 구독 이력이 있는 작품에만 붙습니다. 구독한 적 없이 "목록으로"만 거친 작품은 배지 없이 표시됩니다.

## 설정 화면 순서

설정 탭은 처음엔 **"디스코드 설정"만** 보입니다. 여기서 웹훅 URL을 입력하고 저장하면 그 아래 **"실행 스케줄"**과 **"다운로드 리포트"**가 나타납니다(신작 알림이나 리포트를 보낼 곳이 있어야 그 세부 설정이 의미가 있어서). "다운로드 리포트" 안의 **"미등록 웹툰 중 새 에피소드 섹션 포함"**을 켜면 그 아래 **"카카오웹툰 관리"**가 나타납니다. 이미 저장해두신 값이 있다면 조건을 다시 채우는 순간 그 값 그대로 나타나며, 이 순서는 화면에 보일지 여부만 정할 뿐 저장된 설정 자체에는 전혀 영향을 주지 않습니다. "작가 자동 등록"/"구독해제 관리"/"백업 복원" 카드는 이 순서와 무관하게 항상 보입니다.

## 카카오웹툰 자세히

- **신작 스캔(카카오)**: 등록한 카카오 작가의 새 작품을 찾으면 **구독 상태로 자동 추가**하고 디스코드로 알립니다(네이버 신작 스캔과 같은 동작 — 처음 등록한 작가는 기준선만 저장, 이미 추적 중인 작품이나 제외한 작품은 다시 추가하지 않음). 추가한 작품의 작가도 구독할 때와 같은 규칙(원작자가 있으면 원작자, 없으면 글 작가, 그림 작가 제외)으로 등록하고(구독 시 작가 자동 등록 설정을 따름, 꺼 둔 작가는 그대로) 글/원작 이름을 저장해 둡니다.
- **기다무가 없는 작품(연재무료 등)**: 이용권 응답이 기다무 "사용 가능/사용 중"이라고 해도 작품 정보의 `is_waitfree`가 거짓이면 기다무로 보지 않습니다 — 수동 다운로드 화면에 기다무 항목이 안 나오고, 자동/수동 다운로드도 기다무를 쓰지 않습니다. "N일 후 무료"로 열리는 회차는 잠금으로 표시하되 **무료가 되는 날짜를 "대여 만료" 칸에 `2026-10-07 무료`처럼** 보여줍니다.
- **분석 화면의 회차 수 진단**: 사이트가 말하는 전체 회차 수(`on_sale_count`)보다 가져온 회차(동영상으로 뺀 것 포함)가 적으면 "사이트 회차는 36개인데 31개만 가져왔습니다"라고 경고하고, 숨김 처리되어 표에서 뺀 회차 수도 알려줍니다. 표가 사이트보다 짧아 보일 때 어디서 빠졌는지 가늠하는 용도입니다.
- **설정 탭의 "카카오웹툰 관리"를 켜야** "웹툰 전체목록"/"구독해제"/"제외됨"/다운로드 리포트에 카카오웹툰이 나타납니다(기본은 꺼짐). 꺼도 그동안의 구독/제외 기록은 전혀 지워지지 않고, 다시 켜면 그대로 돌아옵니다.
- **카카오웹툰이 카카오페이지로 통합되어, 지금은 카카오페이지의 웹툰을 다룹니다.** 요일연재("월~일" 탭)에 있는 **연재 중인 웹툰만** 대상이고(웹소설/책은 제외), 완결작은 다루지 않습니다.
- **목록은 캐시를 쓰고 백그라운드에서 갱신합니다.** 카카오페이지는 요일마다 여러 페이지를 받아야 해서(처음엔 10초 안팎) 화면을 열 때마다 받지 않고, 받아둔 목록을 바로 보여줍니다. 목록은 **프로그램이 시작될 때(업데이트 직후 포함), 그리고 3시간마다** 백그라운드로 새로 받아 채우고, "새로고침" 버튼을 눌러도 기다리지 않고 백그라운드로 받습니다(받는 동안 화면에 "백그라운드로 갱신 중"이 표시되고, 끝나면 바뀐 것만 반영됩니다). 저장된 목록이 예전 것으로 굳어버리지 않도록, 시작할 때마다 새로 받고 캐시가 너무 오래되면 화면이 알아채서 다시 받습니다. 일부 요일 조회가 실패하면 멀쩡한 예전 목록을 그대로 둡니다. "웹툰 전체목록"과 "제외됨"의 UP/신작/휴재 배지도 이 목록으로 채웁니다. 화면은 이미 그린 카드는 그대로 두고 **실제로 바뀐 카드만** 갱신하므로, 탭을 오가거나 스크롤해도 카드가 사라졌다 나타나지 않습니다.
- **예전 카카오웹툰 시절의 구독/제외 기록**은 작품 번호 체계가 달라서, 카카오페이지 목록을 **처음 온전히 받은 직후 딱 한 번 자동으로** 카카오페이지 작품으로 변환합니다(전체목록/구독해제/제외됨 모두 — 별도 버튼은 없습니다). **제목이 정확히 하나만 일치하는** 작품만 옮기고(지금 연재 중인 작품은 요일별 목록에서, 완결/휴재 작품은 카카오페이지 검색으로 찾습니다), **못 옮긴 "제외됨" 기록은 지웁니다** — 지금도 연재 중인 작품이면 전체목록에 다시 나타납니다. 구독해제/구독 이력이 있는 기록은 남깁니다. 목록이나 검색이 실패하면 완료로 치지 않고 다음 갱신 때 다시 시도합니다. 관심 작가의 "이미 본 작품" 기준선은 번호가 달라 무의미해져서 시작할 때 자동으로 초기화되고, 다음 스캔에서 알림 없이 조용히 다시 쌓입니다.
- **카카오페이지 다운로드**

- 목록 카드의 작가 이름은 카카오페이지 목록이 주는 대로(글/그림/원작 구분 없이) 표시하고, 구분이 필요한 곳(관심 작가 등록, info.xml)은 작품 "정보"의 글/그림/원작 구분을 씁니다.
- **폴더명 규칙이 네이버와 다릅니다** — 이 프로그램이 직접 받지 않고 사용자가 쓰는 별도 도구가 받아서 저장하다 보니, 콜론(`:`) 같은 금지문자를 이 프로그램(네이버 다운로드)과 다르게 치환합니다(네이버는 전각 콜론 `：`, 카카오는 밑줄 `_`). "뷰어에서 보기" 조회 시 이 차이를 반영해서 찾으므로 신경 쓰실 필요는 없지만, 혹시 웹툰 뷰어 서버 쪽에서 또 다른 규칙을 쓰고 있다면 못 찾을 수 있습니다.
- **표지 이미지**는 카카오페이지 작품 페이지에 나오는 공식 표지(제목이 들어간 이미지)를 보여줍니다. 요일 목록의 카드 이미지는 공식 표지와 다른 그림이라, 작품을 **처음 볼 때** 카카오에서 표지를 받아 저장해두고(이후엔 저장된 것을 씁니다) 화면에 보여줍니다. 그래서 처음 목록을 볼 때는 표지가 조금씩 채워지고, 받지 못한 작품은 카드 이미지로 대신 보입니다. 저장된 표지는 DB 파일 옆 `kakao_cover_cache` 폴더에 있고, 지워도 필요할 때 다시 받아서 채워집니다.

## 아카이빙 자세히

- **아카이빙이 커버/info.xml을 갱신하는 조건**: ① info.xml은 이 앱이 아카이빙 중에 새로 만들지 않고, 작품 폴더에 있는 것(받을 때/메타 동기화 때 최신으로 써 둔 것)을 옮깁니다 — **주기/수동 실행**은 원본을 남기고 복사하며 매번 덮어쓰고, **완결 처리(수동 "완결 처리로 이동"/완결 구독해제 자동 이동)**는 원본을 옮기며 목적지에 있어도 덮어씁니다. ② 커버는 주기/수동 실행에서는 목적지에 이미 있으면 건너뜁니다(없을 때만 복사). ③ **카카오페이지 공식 표지로 교체하는 것은 완결 처리일 때만**이고, 폴더의 info.xml `<Web>`이 카카오페이지 주소일 때만 합니다(옛 카카오웹툰 주소면 안 함 — 메타 동기화로 info.xml을 새로 써야 카카오페이지 주소가 됩니다). 표지를 못 받아도 아카이빙은 계속합니다.
- **아카이빙 대상**은 두 가지로 등록할 수 있습니다 — ① **웹툰으로 등록**(구독 중인 웹툰, 다운로드 폴더 기준) ② **폴더로 등록**(웹툰으로 추적하고 있지 않은 임의 폴더 — 다른 도구로 받으신 카카오웹툰처럼, 이 프로그램이 다운로드하지 않은 폴더도 원본 경로만 지정하면 대상으로 삼을 수 있습니다). 등록 시점에 아래 파일명 변경 프리셋도 바로 지정할 수 있습니다.
- 지정한 대상은 "실행 스케줄"에 설정한 주기마다, **마지막 회차 파일은 남기고** 나머지를 지정한 보관 폴더로 옮깁니다 (마지막 파일을 남기는 이유: 다음 회차를 이어받을 때 "몇 화까지 받았는지" 확인하는 용도로 필요합니다).
- 여러 대상이 **같은 보관 폴더**를 지정하면 자동으로 대상별 하위 폴더로 나뉘고, 하나만 쓰면 그 폴더 바로 밑에 쌓입니다.
- **이미 파일이 있는 폴더도 지정할 수 있습니다** — 다만 폴더 선택 화면에서 "이미 파일이 있습니다"라는 경고가 뜨고, "그래도 선택"을 눌러야 진행됩니다(다른 대상과 폴더가 섞일 수 있다는 걸 알려주기 위한 주의 문구일 뿐, 강제로 막지는 않습니다).
- **완결된 작품을 구독해제하면**(설정에서 켜둔 경우) 지정 여부와 무관하게 **대기열에 등록**되고, "실행 스케줄"이 돌 때 지정 대상의 정기 이동과 함께 처리됩니다(구독해제하는 즉시 옮겨지는 게 아닙니다). 스케줄이 꺼져있으면 "수동 실행"으로 직접 처리할 수 있습니다. 지정 안 된 작품은 별도로 설정한 "기본 보관 폴더"로 갑니다. 이때는 남은 zip 전부와 info.xml/커버 이미지까지 전부 옮기고(같은 이름 파일이 있어도 info.xml/커버는 항상 덮어씀), 다운로드 폴더 쪽에 파일이 하나도 안 남으면 그 폴더도 정리합니다.
- **"수동 실행"에서 완결 처리로 즉시 이동**도 가능합니다 — 지정된 대상을 골라서 "완결 처리로 이동" 체크박스를 켜고 실행하면, 완결 자동이동과 똑같이 마지막 회차까지 전부 옮기고 다운로드 폴더를 정리합니다(연재 중인 작품에도 쓸 수 있으니 실수로 누르지 않게 재확인 절차가 있습니다).
- 주기/수동(부분) 이동에서는 info.xml/커버 이미지를 원본에 남긴 채 보관 폴더로 **복사**만 합니다 — info.xml은 매번 새로 덮어써서 항상 최신 정보를 유지하고(작가/장르 등이 나중에 바뀌어도 반영됨), 커버 이미지는 이미 있으면 건너뜁니다.
- **같은 이름 파일이 이미 있을 때의 처리(건너뛰기/덮어쓰기/이름변경)**는 "아카이빙 공통 설정"에서 하나로 정해서, 주기/수동/완결이동/폴더 일괄이동에 전부 동일하게 적용됩니다.
- **파일명 변경 프리셋**은 "아카이빙 공통 설정"에서 여러 개 만들어 저장해두고, 대상마다(웹툰이든 폴더든) 원하는 프리셋을 골라 적용할 수 있습니다(선택 안 하면 "기본(전역)" 프리셋이 쓰이고, 그것도 비워두면 원본 파일명 그대로 이동). 사용 가능한 토큰: `{title}`(웹툰명), `{episode_no}`(회차 번호), `{subtitle}`(부제목), `{page_count}`(페이지 수), `{author}`(작가명). 토큰을 원하는 순서로 자유롭게 조합하면 됩니다(예: `{title} {episode_no}화 - {subtitle}#{page_count}`). 두 가지 파일명 구조를 인식합니다 — ① 네이버식 `{일련번호} {웹툰제목} {부제목}`(이 경우 `{page_count}`는 zip을 직접 열어서 셈) ② 카카오식 등 제목 없이 `{일련번호}_{부제목}#{페이지수}`로 받은 파일(이 경우 `{page_count}`는 파일명에 이미 적힌 숫자를 그대로 씀 — zip을 안 열어도 되어서, rclone 원격 원본에도 적용됩니다). 둘 다 안 맞는 파일(수동으로 넣은 파일 등)은 원본 파일명 그대로 이동합니다. info.xml/커버 이미지에는 적용되지 않습니다(회차 개념이 없어서). 폴더 일괄 이동에서는 선택적으로만 적용됩니다(아래 항목 참고). **주의**: 회차 번호는 zip 파일명에 이미 적힌 번호를 그대로 신뢰하는데, 네이버식의 경우 이 번호가 실제 네이버 회차 번호가 아니라 "끊김 없는 압축 일련번호"라서, 과거에 회차가 한 번이라도 건너뛴 적 있는 작품은 그 시점부터 실제 회차 번호와 어긋날 수 있습니다.
- **카카오페이지 표지 자동 교체** — 완결 처리(완결 자동이동, 수동 "완결 처리로 이동", 폴더 일괄 이동에서 옵션으로 켠 경우)로 옮겨지는 폴더의 info.xml에 카카오페이지 링크(`page.kakao.com/content/{작품번호}`)가 적혀 있으면, 표지(cover.jpg)를 카카오페이지의 공식 표지 원본으로 새로 받아서 교체해 옮깁니다. 원본이 rclone 원격이어도 폴더 전체를 내려받지 않고 info.xml만 가볍게 읽어서 판별합니다. **옛 카카오웹툰 주소(`webtoon.kakao.com`)가 적힌 info.xml은 카카오페이지의 어느 작품인지 알 수 없어서 건드리지 않고, 원래 있던 표지를 그대로 둡니다.** 받기에 실패해도 아카이빙 자체는 그대로 진행됩니다.
- **폴더 일괄 이동**은 아카이빙 대상 지정과 완전히 별개로, 원본 폴더 안의 **파일들**(폴더 자체가 아님)을 원하는 목적지로 한 번만 옮기고 싶을 때 씁니다(예: 예전에 쌓아둔 백업을 정리할 때, 혹은 완결이라 구독 안 해서 자동 아카이빙 대상엔 못 올리는 웹툰을 다운로드 폴더에서 바로 보관 폴더로 옮길 때). 로컬 폴더와 rclone 원격을 자유롭게 섞을 수 있어서, 로컬→로컬은 물론 로컬↔원격, 원격↔원격 이동도 가능합니다. 로컬을 고르면 ARCHIVE_ROOT/DOWNLOAD_ROOT 중 어느 폴더 기준인지도 고를 수 있습니다. 파일명 변경 프리셋을 하나 골라서 적용할 수도 있고(안 고르면 원본 파일명 그대로), "원본이 카카오웹툰이면 표지 새로 합성해서 옮기기" 체크박스도 있습니다. `{title}` 토큰은 그 파일이 하위 폴더 안에 있으면 그 폴더명을, 최상위에 바로 있으면 원본 폴더 자체의 이름을 씁니다. 이동이 끝나고 원본 쪽에 파일이 하나도 안 남으면 그 폴더도 함께 정리됩니다. 파일이 많으면 시간이 걸릴 수 있어서, "지금 이동"을 누르면 카드 아래에 상태 배지와 진행 로그(몇 번째 파일까지 옮겼는지)가 실시간으로 표시됩니다.

### rclone 원격(원드라이브 등)을 보관 폴더로 쓰고 싶다면

Windows에서 rclone으로 마운트한 드라이브/폴더는 **Docker Desktop이 인식하지 못합니다** (WinFsp 가상 드라이브의 구조적 한계 — 설정으로 해결 불가능한 것으로 확인됨). 대신 이 프로그램이 **컨테이너 안에서 rclone 명령을 직접 실행**해서 원격에 업로드하는 방식을 씁니다 — Windows 쪽 마운트 자체를 거치지 않아서 이 문제가 생기지 않습니다.

컨테이너 안에는 [wiserain/rclone](https://github.com/wiserain/rclone)(원드라이브 안정성 개선이 반영된 포크)의 **항상 최신 버전**이 이미지 빌드 시점마다 자동으로 설치됩니다.

1. Windows PC에서 미리 rclone 설정을 마쳐서 `rclone.conf` 파일을 만들어둡니다 (`rclone config` 명령으로 생성됨, 보통 `%USERPROFILE%\.config\rclone\rclone.conf`)
2. 그 `rclone.conf` 파일이 있는 **폴더**를 docker-compose 환경변수 `RCLONE_CONFIG_HOST_PATH`로 지정
3. "아카이빙" 탭의 폴더 선택기에 **"rclone 원격"** 버튼이 나타나면 정상 연결된 것입니다 — 로컬 폴더와 완전히 동일한 방식(찾아보기/새 폴더 만들기)으로 원격 폴더를 다룰 수 있습니다 (단, "이미 파일 있으면 선택 불가" 확인은 웹툰별 보관 폴더 지정에만 적용되고, 폴더 일괄 이동에는 적용되지 않습니다 — 애초에 파일 많은 폴더를 다루는 게 목적이라서입니다)

## 자주 묻는 질문

**Q. 성인 웹툰이 하나도 안 받아져요.**
쿠키 파일이 제대로 연결되어 있는지, 그리고 로그인이 아직 유효한지 확인해주세요. 쿠키가 만료되면 디스코드로 알림이 갑니다(웹훅을 설정해두셨다면).

**Q. 구독해제나 제외됨 목록에 있는 작품에 태그나 신작 표시가 안 보여요.**
정기적으로(신작 스캔 실행 시) 자동으로 채워지지만, 방금 구독해제/제외하셨다면 아직 한 번도 정보를 못 받아온 상태일 수 있습니다. "작가/태그 관리" 탭의 "지금 전체 재동기화"를 누르시면 즉시 채워집니다.

**Q. 백업은 어떻게 하나요?**
설정 탭에서 "백업 다운로드"를 누르면 지금까지의 구독 목록/설정을 파일 하나로 받을 수 있습니다. 나중에 "복원 파일 선택"으로 그대로 되돌릴 수 있습니다. (디스코드 토큰처럼 민감한 정보는 백업에 포함되지 않으니, 옮기신 뒤엔 다시 입력해주셔야 합니다.)

**Q. 신작 자동 구독을 잠깐 멈추고 싶어요.**
"작가/태그 관리" 탭에서 해당 작가나 태그를 "제외" 버튼으로 꺼두시면 됩니다. 이미 구독 중인 작품 자체는 그대로 유지되고, 그 작가/태그의 **새 작품만** 더 이상 자동으로 안 잡힙니다.

**Q. 완결 작품 아카이빙은 주기 설정이 되나요?**
네. 완결된 작품을 구독해제하면 **즉시 옮겨지는 게 아니라 대기열에 등록**되고, "실행 스케줄"에 설정한 주기가 돌 때 지정 웹툰의 정기 이동과 함께 처리됩니다. 스케줄이 꺼져 있으면(끔) 대기열에 쌓인 채로 남아있으니, "수동 실행"으로 직접 돌려주셔야 합니다.

**Q. 다운로드 리포트에 웹툰 뷰어로 바로가기 링크가 안 붙어요.**
설정 탭에 별도 웹툰 뷰어 서버 주소를 입력해두셔야 합니다. 입력 안 해두면 링크 없이 제목만 나열됩니다.

**Q. 다운로드 리포트에서 "목록 제외" 링크를 눌러도 아무 일도 안 일어나요.**
"설정" 탭에 이 프로그램의 **외부 접속 주소**를 입력해두셔야 링크가 만들어집니다(예: `https://webtoon.example.com`). 안 해두면 미등록 웹툰 항목엔 바로가기만 붙고 "목록 제외" 링크는 아예 안 나옵니다. 링크를 열면 실수 방지를 위해 확인 페이지가 한 번 뜨고, 거기서 버튼을 눌러야 실제로 제외됩니다.

**Q. 다운로드 리포트에 미등록 웹툰 새 에피소드 알림이 나오는 게 싫어요.**
"설정" 탭에서 "미등록 웹툰 중 새 에피소드 섹션 포함" 체크를 끄시면 됩니다.

**Q. "구독해제" 탭에 제가 원하지 않는 웹툰이 섞여 있어요 / 실수로 완전히 사라진 웹툰이 있어요.**
"설정" 탭의 **"구독해제 관리"**를 이용하세요. 구독 이력이 있는데 지금 구독 중이 아닌 웹툰들을 모아 보여주고, 원치 않는 걸 "초기화"하면 완전히 미등록 상태(네이버 요일별 목록에 있는 동안만 "웹툰 전체목록"에 보임)로 되돌아갑니다. 반대로 titleId만 알고 있으면 "구독해제" 상태로 직접 복구하는 것도 가능합니다(이미 구독 중인 웹툰은 이 방식으로 등록할 수 없습니다, 네이버 전용 기능입니다).

**Q. 카카오웹툰이 "웹툰 전체목록"에 하나도 안 보여요.**
"설정" 탭 "카카오웹툰 관리"의 "카카오웹툰 관리하기" 체크가 켜져 있는지 확인해주세요. 이 카드는 "다운로드 리포트"의 "미등록 웹툰 중 새 에피소드 섹션 포함"을 먼저 켜야 나타납니다(그 위의 디스코드 웹훅도 먼저 설정돼 있어야 함) — [설정 화면 순서](#설정-화면-순서) 참고.

**Q. 카카오웹툰의 "구독" 버튼이 안 보이거나 눌러도 소용없어요.**
카카오웹툰의 "구독"은 다운로드가 아니라 웹툰 뷰어 서버에 챙겨보고 있다는 표시라서, "설정 > 다운로드 리포트"에 **웹툰 뷰어 서버 주소**가 입력돼 있어야 구독 버튼 자체가 나타납니다. 안 해두면 "목록제외"만 가능합니다.

**Q. 이 프로그램을 외부(인터넷)에서도 접속하고 싶어요.**
설정 화면에 별도 로그인/인증이 없으니, 리버스 프록시 등으로 앞단에 인증을 붙이시는 걸 권장합니다.

## 개발자용: 코드 구조와 테스트

**구조**
- `app/api/routes.py`는 도메인별 라우터를 `/api` 아래로 묶기만 합니다. 실제 엔드포인트는 `app/api/` 안의 모듈에 있습니다: `webtoons`(네이버 구독 목록), `kakao_webtoons`(카카오 전체목록/구독), `kakao_download`(카카오 로그인/수동 다운로드), `registry`(작가/태그), `manual_download`(네이버 수동 다운로드), `schedule`(실행 스케줄), `discord`, `app_settings`(일반 설정/다운로드 폴더), `jobs`(실행/진행상황), `history`, `system`(백업/복원/도움말), `archive`(아카이빙). 둘 이상의 모듈이 쓰는 모델/헬퍼만 `common.py`에 있고, 모듈끼리는 서로 가져오지 않습니다(모듈 → common 방향만).
- 화면 스크립트는 `app/static/js/`의 파일들로 나뉘어 있고 `index.html`이 **파일 이름 순서대로** 로드합니다(클래식 스크립트라 최상위 선언을 전역으로 공유). `99-main.js`는 다른 파일의 함수를 즉시 참조하므로 반드시 마지막이어야 합니다. 새 파일을 추가할 땐 번호 접두사로 순서를 정하세요.
- 로그 마스킹(`app/log_redaction.py`): 디스코드 웹훅/봇 토큰, 카카오페이지 서명 주소의 `token`/`signature`/`credential` 값, 저장된 카카오 로그인 쿠키 값을 로그에서 가립니다.

**테스트** (`tests/`)
- **깃헙 액션**(`.github/workflows/tests.yml`): 푸시/PR/수동 실행마다 ① 백엔드(Python 3.12, `requirements-dev.txt` 설치 → `pyflakes` 정적 검사 → `python tests/run_backend.py`)와 ② 화면(Node 20, 스크립트 문법 검사 → `npm ci` → `npm test`)을 돌립니다. `tests/backend/test_*.py`와 `tests/js/test_*.js`는 이름 규칙으로 자동 포함되므로 새 테스트는 파일만 추가하면 됩니다. 로컬과 같은 명령이라 깨끗한 환경(가상환경 + `npm ci`)에서 먼저 재현해 볼 수 있습니다.
- 백엔드: `python tests/run_backend.py [이름조각] [--coverage]` — 테스트마다 새 임시 폴더(DB/다운로드/보관/쿠키)로 별도 프로세스에서 돌립니다. 실제 카카오/네이버 서버는 부르지 않고, 응답 형태는 `tests/fixtures/`의 실제 캡처에서 뽑은 샘플을 씁니다.
- 화면: `cd tests/js && npm install && npm test` — jsdom으로 `index.html`과 스크립트들을 브라우저처럼 순서대로 로드해서 확인하고, 스크립트 오류(파일 사이 로드 순서 문제 포함)는 실패로 처리합니다.
- 테스트 실행에 필요한 패키지: 백엔드는 `requirements.txt`와 같고, 화면 테스트만 Node.js가 필요합니다.
- **큰 함수와 특성 테스트**: 80줄을 넘던 함수(아카이빙 폴더 대상/일괄 이동, 네이버 수동·자동 다운로드, 리포트 작업 등)는 "지금 동작을 그대로 고정하는" 특성 테스트를 먼저 쓴 뒤 단계별 작은 함수로 나눴습니다. 이제 코드 줄 기준으로 80줄을 넘는 함수는 없습니다(`bulk_move_folder`는 설명 문서가 길어서 파일상 90줄). rclone이 낀 분기는 `tests/backend/fake_rclone.py`(메모리 안의 원격 폴더)로 흉내 내서 테스트합니다 — 새 테스트에서 `FakeRclone().install()`만 부르면 됩니다. 커버리지는 `python tests/run_backend.py --coverage`로 확인합니다.
